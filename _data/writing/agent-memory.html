Agent 是怎么记住事情的

用户说“按上次的格式来”，Agent 要完成三件事：找到上次的格式，把它放进这次的输入，再据此行动。沿着这条路径看，记忆机制就容易理解了。

2026 年 10 月 · 实现解读

以 SWALM 的 MainAgent 为例，沿着一条信息的保存与读取路径，看看它怎样在需要时被模型看见。

先分清三个地方

当前输入像工作台，放着模型这次能看到的内容；记忆库和文件像资料柜，需要取用；原始轨迹像流水账，记录发生过什么。资料柜里有记录，流水账里有原话，都不代表下一次模型调用已经看到了它。

系统规则、用户请求和近期对话进入当前输入。偏好可以按预算自动注入；过去的任务和日记通过 memory recall 搜索，经验与 Skills 通过 Read 读取。取回的内容进入后续输入，才参与新的判断。

Skills 提供操作手册；经验文件保存已验证的做法。两者都可以读，但来源与更新方式不同。长历史被压缩后，工作台上还会放一份摘要和近期原文，帮助模型接着做。

什么值得保存，谁来保存

内容写入时机再次使用
偏好MainAgent 显式记住、修改或删除按预算自动注入，也可搜索
任务记录Organizer 完成带 TaskCard 的任务搜索摘要与完整轨迹

在挂载统一记忆的同一次运行中，MainAgent 与子 Agent 共用记忆上下文；只有 MainAgent 可以增删改偏好，子 Agent 只读。普通问答没有经过 Organizer 的任务完成钩子，就不会自动变成那类任务记录。

日记也有独立的写入流程：在接近上下文上限时，额外调用模型，从选取的近期内容中提炼可保存的信息。它没有备份每一条工具返回，也不会在每一轮都执行。经验文件则由 Agent 主动编辑。

历史太长，先清理，再考虑摘要

一次长任务会积累大量工具输出。这个实现先尝试替换已经过时的工具正文，保留调用与返回的对应关系，并保护近期完整轮次、Skill 读取和工具发现结果。如果能腾出足够空间，就直接继续。

清理不够时，放弃这次清理草案，将此前的较早历史交给模型总结。新输入由系统规则、历史摘要和近期完整原文组成，再补回预算内的已读 Skills、已发现工具的名称与重新查询提示，以及最新环境状态。

保留近期完整轮次很重要：最近的用户要求、模型动作和工具返回仍然连在一起。摘要承担较早背景，近期原文承担正在发生的工作。原始轨迹另行保留；下一次生成使用的是压缩后的活动段。

这份实现的默认预算

本地估算超过 200,000 tokens 时触发压缩。工具过期方案需同时满足：节省至少 2,000 tokens，剩余不超过 120,000 tokens；最近约 40,000 tokens 的完整轮次受保护。数字是这份配置的触发预算，不等于模型服务的精确计数或窗口上限。

进入摘要分支时，近期原文预算约 12,000 tokens，至少保留一个完整轮次；已读 Skill 恢复预算为 8,000 tokens。活跃偏好的注入预算为阈值的 1%，最多 2,000 tokens。日记默认提前 4,000 tokens 尝试写入。

摘要输入也有预算，超出时可能按整轮丢弃最早历史；更早已过期的工具正文不会从原始日志恢复。摘要为空则保留旧活动段，异常会向上传递。因此，原始轨迹仍需要独立保存。

为什么换个任务就忘了

关键在入口。标准任务入口为每次 attempt 创建空的临时记忆库，结束后归档；下一次 attempt 不会自动读回归档。长驻会话或直接使用配置目录的入口，才可以复用同一份用户记忆。相同的用户 ID，本身不足以保证跨任务继承。

同一会话继续执行，可以沿用当前状态。进程重启后，记忆库、虚拟机里的经验文件、完整对话恢复又是三件需要分别接好的事。保存成功之后，还要检查新入口读的是哪一份存储。

一次线上压缩，留下了什么

历史线上记录中有一次压缩，将 303 条消息变为 98 条。3 条 system 消息保持不变，保留了 7 条较早的 user-role 消息，加入 10,138 字符的摘要，并保留一条 56,945 字符的 Skill 消息。

这里的 7 条 user-role 消息包含环境信息，不能读作 7 次真人请求；字符数也不能当作 token 数。这条轨迹展示了摘要、规则和原文共同保留的结果，前面的阈值则来自当前实现的配置。

旧线上流程在任务末尾生成任务摘要并更新日记；当前实现分别在任务完成、接近压缩阈值、Agent 编辑经验时写入。迁移旧轨迹时，需要连这些生命周期一起对齐。

排查“忘记”，沿一条信息走一遍

比如“报告先给结论”这条偏好：先看它是否写入当前使用的记忆库，再看有没有被注入或检索，最后查看实际发送给模型的输入。如果信息已经在输入里，才继续分析模型是否遵循。这样可以把存储隔离、读取缺失、压缩遗漏和执行偏差分开。

一个好用的记忆系统，需要明确保存什么、何时读取、能跨过哪些边界。最有价值的检查点，是下一次模型调用真正拿到了哪些信息。
