摘要Abstract概要

本报告回溯接手Spec生成任务后，在PE搜索、规则组织、生成架构、评测口径、监督数据和下游执行上的连续实验，必要时引用5月历史基线。核心目标是在一次模型调用中生成符合需求与产品能力的SpecDoc，并验证优化后的准确率和成本。This report traces successive experiments in PE search, rule organization, generation architecture, evaluation protocols, supervision data, and downstream execution since taking over Spec generation, with May baselines where relevant. The goal is to produce a SpecDoc that satisfies requirements and product capabilities in one model call, and to measure its accuracy and cost.Spec生成を担当して以降のPE探索、ルール整理、生成構造、評価条件、教師データ、下流実行の実験を振り返り、必要に応じて5月の基準値を参照する。目的は、一回のモデル呼び出しで要求と製品能力に適合するSpecDocを生成し、精度とコストを検証することにある。

主要发现有四点。第一，定点修改改善了部分目标问题，但四域联合通过率仍受其他题退化影响，局部检查与全量验收需要配合使用。第二，呈现规范化和直接搬运高分样本特征出现多组回退，重构由此转向职责分层与字段依赖规划。第三，分层生成PE在七月统一口径下取得Dev150 16/150、Former50 31/50，Dev平均输入约8.8k；后续八轮搜索0 KEEP，同一PE两次全量运行有19题翻转，重复性成为下一阶段重点。第四，人工PE专项的动态策略记忆取得历史KEEP，后期继续训练配置在Building0.7同题对照中由32/50升至35/50。各阶段按题集与Judge分别报告。Four findings stand out. Targeted edits improved some cases, but regressions elsewhere limited four-domain joint accuracy, requiring both local and full-set checks. Presentation normalization and direct transfer of high-scoring sample features repeatedly regressed, shifting restructuring toward responsibility layers and field dependencies. Under July's unified protocol, the layered PE achieved 16/150 on Dev150 and 31/50 on Former50 at about 8.8k Dev input tokens; eight subsequent search rounds yielded no KEEP, and two full runs of the same PE flipped 19 cases, making repeatability the next priority. Dynamic strategy memory produced historical KEEPs in the human-PE track; later, continued training improved a paired Building0.7 result from 32/50 to 35/50. Results remain grouped by dataset and Judge.主な知見は四つある。局所編集で目標ケースは改善したが、他ケースの悪化が四領域同時合格率を制約し、局所確認と全件検証の併用が必要だった。表現の正規化と高得点例の表面的特徴の移植は複数回悪化し、責務の分離とフィールド依存の設計へ方針を転換した。7月の統一条件では、階層型PEがDev150で16/150、Former50で31/50、Dev平均入力約8.8kを達成した。その後の八回の探索はKEEPゼロで、同じPEの全件実行二回で19問が反転し、再現性が次の焦点となった。人手PE系統では動的戦略メモリがKEEPを獲得し、後期の継続学習設定はBuilding0.7の同一問題比較で32/50から35/50へ改善した。各段階はデータセットとJudge別に報告する。

1　任务与评测范围1 Task and evaluation scope1　タスクと評価範囲

输入为用户Query及其澄清Q&A，输出是下一步搭建系统要消费的Lite SpecDoc。七月主线要求一次Seed2调用直接生成，不依赖外部Planner、生成后LLM repair、Contract剥离或best-of。离线Harness可使用多Agent分析和修改下一轮PE，这不改变线上调用次数。The input is the user query and clarification Q&A; the output is a Lite SpecDoc consumed by the downstream builder. July's main track requires one direct Seed2 generation call, without external planners, post-generation LLM repair, contract stripping, or best-of selection. The offline harness may use multiple agents to analyze and revise the next PE without changing the online call count.入力はユーザーQueryと確認Q&A、出力は下流の構築処理が利用するLite SpecDocである。7月の主系統はSeed2一回での直接生成を要件とし、外部Planner、生成後のLLM修正、Contract除去、best-of選択を使わない。オフラインHarnessで複数Agentが分析し次のPEを変更しても、オンライン呼び出し回数は変わらない。

评测主要有两类：Spec Judge检查设计文档；E2E Judge检查执行器搭建的Base。文档通过后仍需验证实际产物。十月Building Mix与七月四域strict使用不同评测对象和指标。Spec Judges evaluate design documents; E2E Judges evaluate the Base built by the executor. Passing the document check does not replace artifact validation. October's Building Mix and July's four-domain strict evaluation use different objects and metrics.Spec Judgeは設計文書を、E2E Judgeは実行器が構築したBaseを評価する。文書合格後も実成果物の検証が必要である。10月のBuilding Mixと7月の四領域strictでは、評価対象と指標が異なる。

Spec主线采用四域联合通过率：Table、Dashboard、Workflow、Permission均通过才计为整题通过。领域分数用于定位问题，全量通过数用于验收PE；E2E结果则按对应Building版本单独报告。The main Spec metric is joint four-domain pass rate: a case passes only if Table, Dashboard, Workflow, and Permission all pass. Domain scores locate problems; full-set pass counts accept or reject a PE. E2E results are reported separately for each Building version.Specの主指標は四領域同時合格率で、Table・Dashboard・Workflow・Permissionの全てに合格して初めて一問合格となる。領域別スコアは原因特定に、全件合格数はPE採否に用いる。E2E結果はBuildingのバージョン別に報告する。
