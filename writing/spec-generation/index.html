Spec generation

Generating Better Specs让模型写好设计文档設計仕様をよりよく生成する

From automated prompt search to a structured generation protocol: experiments in organizing rules, planning dependencies, and testing changes.从提示词自动搜索到生成协议重构，几个月的实验逐渐把问题落到了规则组织、依赖规划和修改验收上。プロンプトの自動探索から生成手順の再設計へ。ルールの整理、依存関係の計画、変更の検証を重ねた実験の記録。

Yecheng Zhang · 张业成 Research notes研究记录研究記録 · 2026.06–10

Give each rule a clear role先让规则各司其职ルールの役割を明確にする

“Notify the owner when this month’s orders exceed a threshold.” A useful spec must define the time window, aggregation, condition, and recipient. Fields used by dashboards and workflows need to exist in the tables first.用户提出“本月订单超过阈值时提醒负责人”，设计文档就需要把时间范围、统计方式、判断条件和接收人写清楚。看板与工作流使用的字段，也要先在数据表中定义。「今月の注文がしきい値を超えたら担当者に通知する」。この要件には、集計期間、集計方法、判定条件、通知先の定義が必要になる。ダッシュボードやワークフローが使うフィールドも、先にテーブルに定義しなければならない。

We explored targeted edits, guarded patch search, and strategy memory updated from failures. We then restructured the prompt itself: Core orders understanding and planning, Shared holds cross-domain rules, and Domain Skills define capabilities and design methods.我们尝试过定点编辑、受保护的补丁搜索，以及从失败中更新策略记忆。随后，工作转向提示词本身的结构：Core安排需求理解和规划顺序，Shared保存跨域规则，各领域Skills负责能力边界和具体设计方法。局所的な編集、制約付きのパッチ探索、失敗から更新する戦略メモリを試した後、プロンプトの構造を見直した。Coreは理解と計画の順序を、Sharedは領域横断のルールを、Domain Skillsは機能の制約と設計方法を担う。

The full essay follows these experiments: what each change improved, where regressions appeared, and which designs we kept.这篇文章沿着实验顺序，回顾每种改动解决了什么、在哪些地方发生回退，以及最后保留了哪些设计。全文では実験の順に、各変更で改善した点、性能が下がった箇所、最終的に採用した設計を振り返る。
